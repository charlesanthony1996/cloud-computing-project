# ADR-001: Microservices based architecture with docker compose

## Status
Accepted

## Context
The project requires a scalable, modular system that integrates data ingestion, machine learning inference, control logic, and monitoring.
The system must support independent development, testing and deployment of components while remaining simple enough for local execution and demonstration

A monolithic architecture would tightly couple data generation, preprocessing, ML inference and control logic , making experimentation and observability difficult

## Decision
We adopt a **microservices based architecture** implemented using **Docker containers orchestrated with docker compose**

Each core responsibility is implemented as an independent FastAPI service:
- Generator service (data simulation)
- Ingestion service (buffering and coordination)
- Feature extractor service (preprocessing)
- Anomaly detection service (ML inference)
- Carbon controller service (rate control logic)
- Monitoring stack (prometheus & Grafana)

Services communicate over HTTP using well defined REST endpoints

## Consequences

### Positive
- Clear seperation of concerns improves maintainability and readability
- Services can be scaled, modified or replaced indpendently
- Aligns with real world cloud native and MLOps practices
- Simplifies observability and monitoring per component
- Enables realisitic CI/CD and deployment discussions

### Negative
- Higher operational complexity than a monolith
- requires network communication and service coordination
- slightly increased latency between pipeline stages

## Alternatives Considered
- **Monolithic Fastapi application**
Rejected due to tight coupling and limited scalability
- **kubernetes based deployment**
Rejected as overkill for project scope and grading requirements

## sustainability considerations
Microservices allow selective scaling (e.g., increasing data generation rate only when needed), reducing unncessary compute usage and energy consumption.
Containerization also enables reproducible and region aware deployment strategies.
