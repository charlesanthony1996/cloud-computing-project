# ADR-002: Streaming ML inference pipeline with window based LSTM

## Status
Accepted

## Context
The system processes continuous IMU sensor data and must detect freezing of gait events using a machine learning model.
Real time inference requires handling streaming data, fixed length inputs, and preprocessing before model execution

Raw sensor data is noisy and variable in length, while the ML model expects a fixed size input tensor

## Decision
We implement a **window based streaming pipeline**
1. Sensor samples are ingested continuously
2. Samples are buffered until a fixed window size (128 timesteps) is reached
3. The window is normalized in a dedicated feature extraction service
4. A lightweight LSTM model performs binary FoG classification

Each pipeline stage is isolated in its own service

## Consequences


### Positive
- Clear, explainable ML pipeline
- Supports streaming and batch style inference
- Decouples ML logic from preprocessing and ingestion
- Easy to replace or retrain the ML model
- Compatible with real-time monitoring and control loops

## Negative
- Fixed window size introduces detection latency
- Padding may slightly affect prediction quality
- Requires buffer management and synchronization

### Alternatives Considered
- **Frame by frame inference**
Rejected due to poor temporal modeling
- **Transformer based models**
Rejected due to higher computational cost and energy sources
- **Online learning models**
Rejected due to complexity and reproducibility concerns

## Sustainability considerations
Using a compact LSTM minimizes compute and energy consumption compared to larger deep learning models
Window based inference avoids continuous model execution, reducing unnecessary CPU usage
